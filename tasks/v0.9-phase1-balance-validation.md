# v0.9 Phase 1 — Balance-Continuity Validation

Read `HANDOVER.md` top section first. Follow all conventions in `CLAUDE.md` (Next.js 16 rules, no module-level Sheets singleton, API error shape `{ error: string }`, `export const dynamic = 'force-dynamic'` on API routes).

## Why

v0.8.1 debugging found Tesseract OCR silently dropping a leading digit from HSBC statement amounts/balances (982.39 → 82.39). The only reliable catch was manually checking that each row's running balance equals the previous balance ± the transaction amount. Automate that check.

## What to build

### 1. `src/lib/expenses/validate.ts` (new)

```ts
import type { ExpenseTransaction, BalanceContinuityIssue } from '@/types';

export function validateBalanceContinuity(txs: ExpenseTransaction[]): BalanceContinuityIssue[];
```

Add to `src/types/index.ts` (all shared types live there — do not define inline):

```ts
export interface BalanceContinuityIssue {
  account: string;
  id: string;          // offending transaction id
  date: string;
  description: string;
  expectedBalance: number;  // prevBalance ± amount
  actualBalance: number;
  prevId: string;      // transaction the expectation was computed from
}
```

Logic:
- Group transactions by `account`. Skip transactions with `balance == null` (credit-card parsers don't emit balances; deposit parsers `hsbc-composite.ts` and `uob-deposit.ts` do).
- Within an account, order rows by `date` ascending, **preserving original array order for same-date rows** (sheet order = statement order; a plain stable sort by date is correct — do not sort by anything else).
- Walk consecutive pairs: expected = `prev.balance + amount` if `direction === 'credit'`, `prev.balance - amount` if `'debit'`. Flag when `|expected - actual| > 0.005` (float tolerance).
- First row of each account has no predecessor — never flagged.
- Return issues in walk order.

Note: consecutive statements chain (closing balance = next opening), so cross-statement continuity is expected to hold and mismatches there are real signals, not noise.

### 2. Wire into the import pipeline

In `src/lib/expenses/pipeline.ts`, after `appendExpenses(newRows)`:
- If `newRows.length > 0`: fetch the full sheet via `getExpenses()` (from `./sheets`), filter to only the accounts present in `newRows`, run `validateBalanceContinuity`, and keep only issues whose `id` is in `newRows` **or** whose `prevId` is in `newRows` (don't re-report pre-existing issues on every import).
- Add `continuityIssues: BalanceContinuityIssue[]` to `ImportResult`.
- Append issues to `import.log`, one line each: `CONTINUITY: <account> <date> "<description>" expected <expected> got <actual>`.

### 3. On-demand full-sheet validation

- New API route `src/app/api/expenses/validate/route.ts` — `GET`, `export const dynamic = 'force-dynamic'`, Web `Request`/`Response.json`. Calls `getExpenses()` → `validateBalanceContinuity` over everything → `Response.json({ issues })`. 500 with `{ error: string }` on failure.
- UI: in `src/components/expenses/ExpensesClient.tsx`, transactions tab, add a small "Validate balances" button near the import button. On click, fetch the route; show either "No continuity issues" or a compact list (date, account, description, expected vs actual, S$ format `S$1,234.56`). Match the existing panel/button styling in that file. Keep it minimal — this is an audit tool, not a dashboard feature.

### 4. Import UI

`src/components/expenses/ImportButton.tsx` renders the import result — display `continuityIssues` (if any) as a warning section in the same result panel.

## Tests

Vitest, colocated under `src/lib/expenses/__tests__/validate.test.ts` (match existing test style there). Cover:
- Clean sequence → no issues.
- Dropped-digit balance (mid-sequence) → exactly that row flagged with correct expected value.
- Direction handling: credit adds, debit subtracts.
- Same-date rows keep input order (construct a case that would fail if re-ordered).
- `balance: null` rows skipped without breaking the chain (chain continues from last non-null balance row? No — simpler: null-balance rows are ignored entirely for the walk).
- Multiple accounts validated independently.
- Rounding: 0.005 tolerance not falsely triggered by float arithmetic.

Run only the new test file plus `npm run build` type-check equivalent (`npx tsc --noEmit`) — do not run the full suite unless something fails.
