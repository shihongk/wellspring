# v0.9 Phase 2 — Extended Rules Engine

Read `HANDOVER.md` top section first. Follow all conventions in `CLAUDE.md`. Phase 1 (`tasks/v0.9-phase1-balance-validation.md`) is already merged.

## Why

Four backlog items collapse into one mechanism:
1. Credit-card bill payments (`GIRO PAYMENT`, `AUTOPAY`, `BILL PAYMENT`) parse as `credit` direction and show up as income.
2. Self-transfers between own accounts double-count in income + spending.
3. Recurring junk transactions (the $1.00 HSBC `OTHR`/`HIB-` verification transfers) must be manually excluded per row on every import.
4. `Other` still catches too much.

Today `ExpenseRules` is `merchant substring → category` only. Generalize: **match** (description-contains + optional account + optional exact amount + optional direction) → **action** (set category and/or set excluded). No regex — structured fields only. Extend the existing rule-creation flow; do not build a parallel one.

## Data model

Extend `ExpenseRule` in `src/types/index.ts`:

```ts
export interface ExpenseRule {
  merchant: string;                  // case-insensitive substring match on description
  category?: string;                 // action: set category (optional now)
  account?: string;                  // match: exact account name
  amount?: number;                   // match: exact amount (±0.005)
  direction?: 'debit' | 'credit';    // match
  exclude?: boolean;                 // action: set excluded=true
}
```

`ExpenseRules` sheet columns become `A merchant | B category | C account | D amount | E direction | F exclude` (`'true'`/empty). **Backwards compatible**: existing rows only have A–B populated; empty C–F mean "no constraint / no exclude action". Update `getExpenseRules` and `upsertExpenseRule` in `src/lib/expenses/sheets.ts` to read/write `A:F`. A rule must have at least one action (category or exclude).

## Matching engine

Rework `src/lib/expenses/categorize.ts`:

```ts
export function ruleMatches(tx: ExpenseTransaction, rule: ExpenseRule): boolean;
// all specified match-fields must hold (AND semantics)

export function applyRules(tx: ExpenseTransaction, userRules: ExpenseRule[]): { category: string; excluded: boolean };
```

- Category: first matching rule (user rules first, then `BUILT_IN_RULES` map, then built-in structured rules below) that has a `category`; fallback `'Other'`. Preserves today's precedence: user rules override built-ins.
- Excluded: true if **any** matching rule (user or built-in) has `exclude: true`.
- Keep the existing `BUILT_IN_RULES` merchant→category map in `src/lib/constants.ts` as-is; add a new `BUILT_IN_STRUCTURED_RULES: ExpenseRule[]` alongside it:
  - `{ merchant: 'GIRO PAYMENT', category: 'Transfer' }`
  - `{ merchant: 'AUTOPAY', category: 'Transfer' }`
  - `{ merchant: 'BILL PAYMENT', category: 'Transfer' }`
  - `{ merchant: 'PAYMENT RECEIVED', category: 'Transfer' }` (Amex wording — verify against `amex-credit.ts` before adding)
  - `{ merchant: 'HIB-', amount: 1.00, exclude: true }` (the HSBC verification transfers; verify the exact stable substring against real descriptions — they look like `SGV02056JGB61HMQ ... HIB- 363236X591802 ... OTHR`)

In `src/lib/expenses/pipeline.ts`, replace the `categorize(...)` call: run `applyRules` for every parsed tx — category assigned only when parser left `'Other'` (preserve parser-assigned categories, current behaviour), `excluded` applied always (`tx.excluded = true`).

## Retroactive application

Extend `applyRuleToExisting` in `src/lib/expenses/sheets.ts` to accept a full `ExpenseRule`:
- Category action: update category (column I) on matching rows whose category is `'Other'` (current behaviour).
- Exclude action: set excluded (column L) to `'true'` on **all** matching rows not already excluded.
- Matching must use the same logic as `ruleMatches` — read enough columns (`A:M`) to evaluate account/amount/direction. Reuse the function; don't duplicate the predicate.
- Update the server action in `src/app/lib/actions.ts` that calls it (keep `revalidatePath` behaviour).

## Merchant sweep helper (backlog item 4)

New script `scripts/list-other-merchants.ts` (follow `scripts/` conventions in `CLAUDE.md`: dotenv from `.env.local`, run via `npx tsx`): fetch all expenses, group `category === 'Other'` rows by a normalized description prefix, print count + total per group, sorted by count desc, top 40. Output is for the user to pick new built-in rules from — do not invent merchant rules yourself beyond the structured ones above.
