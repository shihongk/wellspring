# v0.9 Phase 3 — Retirement Inputs From Real Data

Read `HANDOVER.md` top section first. Follow all conventions in `CLAUDE.md`. Read `cpf-retirement-KB.md` before touching CPF logic. Phases 1–2 are already merged.

## Why

`src/app/retirement/page.tsx` passes hardcoded `initialGrossMonthlySalary={9000}` and `initialNetMonthlyCashFlow={3000}` to `RetirementClient`. Both should derive from real data. The override plumbing (`grossMonthlySalaryOverride` / `netMonthlyCashFlowOverride`, persisted in localStorage) already exists and must keep working — this phase only changes the *derived initial* values that overrides fall back to.

## 1. Gross monthly salary — from CPF `CON` transactions

New function in `src/lib/retirement/` (e.g. `salary.ts`, exported; type additions go in `src/types/index.ts` if any):

```ts
export function deriveGrossMonthlySalary(cpfTransactions: CpfTransaction[], userAge: number): number | null;
```

- Filter to `code === 'CON'` rows. Group by month (`date.slice(0, 7)`).
- Monthly total contribution = sum of `oaChange + saChange + maChange` for that month's CON rows.
- Take the most recent month's total; divide by the total contribution rate for `userAge` from the CPF rate brackets in `src/lib/constants.ts` (the same table `src/lib/retirement/cpf.ts` uses — reuse, don't duplicate).
- Return `null` when there are no CON rows (caller falls back to 9000).
- Note: result is capped by the CPF salary ceiling by construction. That is intentional and correct here — the projection uses gross salary only to compute CPF contributions, which are ceiling-capped anyway. Add this as a brief comment (non-obvious WHY).

In `retirement/page.tsx`: the page (or its data layer) already has access to `getCpfTransactions()` from `src/lib/retirement/sheets.ts` — add it to the existing `Promise.all`, derive, and pass `initialGrossMonthlySalary={derived ?? 9000}`. Compute `userAge` the same way the expenses page does (DOB June 1984 — find the existing age computation and reuse it rather than re-deriving).

## 2. Net monthly cash flow — from the expense projection engine

`RetirementClient` (`src/components/retirement/RetirementClient.tsx`) already computes per-year `{ income, expenses }` from `computeBaselineAverages` + `generateProjections` in a `useMemo` (used by the chart tooltip). Derive the initial net monthly cash flow from that same computation — first projection year's `(income − expenses) / 12` — instead of the `initialNetMonthlyCashFlow` prop value:

- Precedence: `netMonthlyCashFlowOverride ?? derivedFromProjections ?? initialNetMonthlyCashFlow` (prop stays as final fallback; keep passing `3000` from the page).
- The settings-panel input placeholder currently shows `initialNetMonthlyCashFlow` — show the derived value there instead when available, so the user sees what the model actually uses.
- Reuse the existing `useMemo` result; do not run the projection engine a second time.

## 3. Same for gross salary display
