# Task: v0.7 Phase 6 — Navigation & Provisioning

## What this task builds

This is the final cleanup phase for v0.7. It involves adding a UI component to the `/setup` page to help users on older versions of the spreadsheet schema migrate to the new retirement-related tabs.

The "Retirement" nav link was already added in Phase 5. The `provision` route was updated in Phase 1. This is the last remaining task.

---

## Project Context & Rules

- **Framework:** Next.js 16.2.3 App Router (TypeScript, Tailwind CSS v4)
- **API Endpoint:** The component will call `POST /api/setup/migrate-retirement`, which already exists.
- **Idempotency:** The API is idempotent. The UI should handle the `alreadyExists: true` response gracefully.

---

## Files to Create/Edit

### 1. Create `src/components/setup/MigrateRetirementSection.tsx`
- Create as a `'use client'` component.
- It should follow the pattern of previous migration sections on the setup page.
- **Props:** It should accept `spreadsheetId: string`, `serviceAccountEmail: string`, `privateKey: string` as props from the parent `Setup` page component.
- **UI:**
  - A descriptive header: "v0.7 Retirement Features"
  - A paragraph explaining that this will add the `CpfBalances` and `RetirementOneOffs` tabs to their sheet.
  - A button: "Add Retirement Tabs"
- **State Management:**
  - Manage the fetch state: `idle` | `running` | `done` | `already-exists` | `error`.
  - The button should be disabled when `running`.
  - Display status messages based on the state (e.g., "✓ Tabs already exist", "✓ Retirement tabs created successfully.", "Error: ...").
- **Logic:**
  - The button's `onClick` handler should `POST` to `/api/setup/migrate-retirement`, sending the credential props in the request body.

### 2. Edit `src/app/setup/page.tsx`
- Import and render `<MigrateRetirementSection />`.
- Pass the credential state from the setup page's form fields down to the new component as props.

---

## Acceptance Criteria

1. The new migration section appears on the `/setup` page.
2. Clicking the button successfully calls the API and adds the tabs to a sheet that doesn't have them.
3. Clicking the button on a sheet that already has the tabs shows the "already-exists" message.
4. All UI states (loading, error, etc.) work correctly.
5. Run `npx tsc --noEmit` and ensure 0 errors.
